# EEF Node (`eefn`)

Everything "node" for EEF, in one repo — the companion to the `eef` coordinator.

- The **`eefn/` Python package** is the single source of truth: wire crypto +
  protocol, the node engine (capabilities a PC node offers), the long-running
  node client, and the coordinator-side node server (`eefn.server`).
- The **flat standalone bundle** in `node/` is generated from the package by
  `tools/emit_node.py` and zipped into `dist/eef-node-dist.zip`. A fresh node
  runs that flat bundle with only Python 3.11+ and `cryptography` — no EEF
  package installed.

The coordinator (`eef`) depends on this package and imports `eefn.server` for its
node gateway. Fresh machines provision from this repo on **GitHub**.

## Layout

```
eefn/            the importable package (source of truth)
  crypto.py      AES-256-GCM + HMAC over a PSK-derived key
  protocol.py    newline-JSON wire protocol
  engine.py      node capabilities (system.ping, filesystem, launch_application, llm.infer, vlm.analyze)
  client.py      node client: ordered-endpoint failover, signed AUTH, register, heartbeat
  server.py      coordinator-side NodeServer (TCP gateway)
node/            FLAT standalone bundle (generated by tools/emit_node.py)
  node_crypto.py node_protocol.py node_engine.py node_client.py run_node.py start.cmd
tools/
  emit_node.py       regenerate node/ from eefn/
  make_node_dist.py  zip node/ -> dist/eef-node-dist.zip
  bootstrap_eef.py   pull the dist from GitHub -> C:/eefn
install.ps1      PowerShell one-liner wrapper
config.example.json   sample node config (endpoints: Radmin, then Playit — no port needed)
dist/eef-node-dist.zip  committed, pulled by the bootstrap from GitHub
```

## Provision a brand-new PC node (one command, from GitHub)

```powershell
powershell -nop -c "irm https://raw.githubusercontent.com/eepyfishy/eefn/main/install.ps1 | iex"
# or, with the single bootstrap file on hand:
python bootstrap_eef.py --psk SECRET
```

Pulls `dist/eef-node-dist.zip` from the GitHub repo, extracts to `C:/eefn`, writes
`config.json` (`node_id`, `name`, `psk`, ordered endpoints), ensures `cryptography`.

## Run a provisioned node

```bash
cd C:\eefn
python run_node.py                 # connects (primary Radmin, fallback Playit) and serves
python run_node.py --allow-write   # also allow filesystem writes
```

`node.eeftuna.playit.plus` needs **no port** — it already points to 8081 by default; the
client defaults to 8081 when no port is given.

## For developers of this repo

```bash
pip install -e .[dev]
python tools/emit_node.py --check      # fail if node/ is out of sync with eefn/
python tools/emit_node.py              # regenerate node/
python tools/make_node_dist.py         # rebuild dist zip
python -m pytest tests/                # node-system tests
```

Then commit the regenerated `node/` and `dist/` so GitHub stays the source of truth.

## Security

- Every message **AES-256-GCM** encrypted (shared PSK); no plaintext/XOR fallback.
- Nodes authenticate with a **signed AUTH** handshake (HMAC over
  `nonce|node_id|version|timestamp`). Wrong key → encrypted `denied` + drop.
- `filesystem.write` is denied unless the node runs with `--allow-write`.
